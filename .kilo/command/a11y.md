# /a11y

Accessibility audit.

## Usage

```
/a11y [page path]
```

## Behavior

1. Load `skills/accessibility/` for project-specific patterns
2. If a page path is given, audit that page. Otherwise audit `/`, `/projects`, `/projects/async-threat-platform`
3. Check for:
   - ARIA attributes (correct roles, labels, descriptions)
   - Focus management (traps, returns, visible indicators)
   - Keyboard navigation (all interactive elements reachable)
   - Color contrast (use the token × theme matrix from `contrast.test.ts`)
   - Reduced motion support
   - Screen reader announcements (live regions, error messages)
4. Run `pnpm test:e2e` if Playwright tests exist for the page
5. Report findings with file:line references

## Common issues to check

- Theme toggle `aria-label` describes next action, not current state
- Palette popup uses correct ARIA pattern (menu or disclosure)
- Contact form errors linked via `aria-describedby`
- Mobile drawer traps focus and sets `inert` on background
- `scroll-behavior: smooth` disabled in reduced-motion
